# CKA Domain Practice Map

This map uses the section structure in the [KodeKloud CKA course notes](https://notes.kodekloud.com/docs/Certified-Kubernetes-Administrator-CKA/). It is a learning crosswalk, not a claim that this repository reproduces the course or defines the current CKA exam blueprint. The linked notes describe a broad curriculum of core objects, scheduling, observability, application lifecycle, maintenance, security, storage, networking, cluster design and installation, troubleshooting, Helm, Kustomize, JSONPath, and mock exams. Course pages can change; check the current [CKA certification information](https://www.cncf.io/training/certification/cka/) and Kubernetes documentation before exam preparation or production work.

The playbook focuses on practical operations, not on copying course lesson text. The [end-to-end release lab](../../03-gitops-and-strategy/end-to-end-release-lab/README.md) supplies a running local app and a complete answer key; use this map to extend it into a broader Kubernetes practice path.

## Suggested Practice Order

1. Complete the [release lab](../../03-gitops-and-strategy/end-to-end-release-lab/README.md), including both failure drills and its [answer key](../../03-gitops-and-strategy/end-to-end-release-lab/answer.md).
2. Work through the focused [RBAC](02-rbac-and-namespaces.md), [probe](03-probes-healthchecks.md), [autoscaling](04-autoscaling.md), and [architecture](01-architecture-deep-dive.md) exercises.
3. Use this coverage map to select one gap at a time. Capture commands and observed output, not just a claim that a resource applied.
4. Reserve node maintenance, control-plane upgrades, etcd restore, and kubeadm installation for disposable multi-node VMs with a recovery path.
5. Re-run the exercises without notes in a fresh cluster and explain the evidence and rollback as you go.

## Safety and Version Notes

- Never practice on a cluster unless you own it or have explicit authorization. Confirm `kubectl config current-context` before every destructive operation.
- Use dummy values for Secrets. Kubernetes Secret data is not encrypted merely because it is base64-encoded; use an approved secret manager and cluster encryption controls for real credentials.
- Kind is excellent for API-object, rollout, and application-level practice. It does not reproduce a real host upgrade, production CNI behavior, cloud load balancer, managed control plane, or every CSI driver.
- Verify feature availability and command behavior against the Kubernetes version in your lab. Exam objectives and course notes may be revised independently.
